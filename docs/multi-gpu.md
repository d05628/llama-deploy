# CUDA 多 GPU 配置

管理器会列出每张 NVIDIA GPU 的编号、UUID、名称、总显存和当前可用显存。GPU 配置与系统信息页显示已保存配置对应的分配计划。保存设置会刷新设备信息与建议；运行中的模型需要重启后才会使用新设置。

双卡及更多 CUDA 显卡共用同一组设置。默认 `multi_gpu: "auto"` 优先使用选中的主卡：模型预计能放入主卡时使用单卡，需要更多显存时再拆分到多张卡。小模型使用多卡不保证更快；应在实际模型、上下文与并发负载下比较。

## 管理器设置

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `gpu.multi_gpu` | `"auto"` | `auto` 按模型与显存规划；`off` 限定主卡；`force` 要求多卡，至少需要两张可用 CUDA 显卡。 |
| `gpu.main_gpu` | `"auto"` | 按可用资源自动选择主卡，也可指定 NVIDIA 设备编号或 UUID，例如 `0`、`"GPU-…"`。管理器下拉列表使用设备编号，并保留已有 UUID 配置。 |
| `gpu.split_mode` | `"layer"` | `layer` 按层拆分；`row` 按行拆分。建议从 `layer` 开始，是否改用 `row` 由实测决定。 |
| `gpu.tensor_split` | `""` | 留空按可用显存自动计算。自定义值为逗号分隔的非负数，至少一项大于 0，按引擎设备顺序给出每张候选显卡的相对权重，例如 `"2,1"`。 |
| `gpu.reserve_mb` | `1024` | 多卡规划时每张卡额外预留的显存，单位 MiB。单卡默认行为保持原有规划逻辑。 |

多 GPU 设置针对 CUDA。选择 CPU、Vulkan 或其他后端时，应以计划说明和启动日志中的实际参数为准。

设备编号来自 NVIDIA 硬件列表，启动参数使用引擎 `--list-devices` 返回的 `CUDA…` 名称；两者的顺序可能不同。启动器按名称和容量匹配身份，并尊重引擎可见设备列表。对于无法唯一匹配的同名同容量设备，自动模式仍可按引擎报告的可用显存规划；手动 UUID/编号选择会明确报错，避免误选另一张卡。更换设备或设置 `CUDA_VISIBLE_DEVICES` 后需重新检查自定义比例。

`layer` 把各层对应的 KV cache 随层拆分；`row` 的完整 KV cache 与中间结果仍集中在主卡，即使给主卡设置零权重也受该卡上下文容量限制。GPU 视觉模块会显式绑定到计入预算的主卡；若旧引擎无法指定该设备，需要升级或将视觉模块放 CPU。不会自动启用 `tensor` 拆分模式。

`row` 多卡模式要求使用 `--list-devices` 返回的完整 CUDA 设备集合，并保持 `CUDA0,CUDA1,…` 自然顺序。若空闲显存不足导致候选设备被筛掉，或设备列表重排/不连续，启动器会明确报错；请释放各卡余量或改用默认 `layer`。这是因为 CUDA 行拆分的比例与主卡索引需要对应完整后端设备数组，不能把筛选后的紧凑索引当成全局索引。`CUDA_VISIBLE_DEVICES` 在引擎初始化前生成的完整可见设备集合仍按该枚举验证；单卡 `none` 模式不受此限制。

Bonsai Prism 的当前固定运行时另有 row 跨卡兼容问题，因此对该量化强制使用已验证的 layer 路线；不因命令行接受 row 参数就宣称该模型能使用它。其他模型仍遵守上述设备顺序限制。

配置示例：

```json
{
  "gpu": {
    "backend": "cuda",
    "gpu_layers": -1,
    "flash_attention": true,
    "multi_gpu": "auto",
    "main_gpu": "auto",
    "split_mode": "layer",
    "tensor_split": "",
    "reserve_mb": 1024
  }
}
```

保留 `gpu_layers: -1` 可让启动器根据预算自动拟合卸载层数。手动指定卸载层数、自定义分配权重或强制多卡时，仍需确认实际显存足够。

## 与 TTS、VRM 等程序共用 GPU

先启动准备同时使用的程序，再查看管理器里的逐卡可用显存。自动分配会参考当前资源；可提高每卡预留，给后续增加的音频、动画或显示负载留余量。预留值为每张卡分别扣除的规划余量，并不限制其他程序继续分配显存。

两张 16 GiB 显卡依然是两个独立设备。管理器可以拆分模型权重，但不会把它们变成一张 32 GiB 显卡。KV cache、计算缓冲区、视觉投影及主卡额外工作也占显存，不能只把模型文件大小与总显存相加比较。

自定义 `"2,1"` 是约 2:1 的分配权重，不代表 2 GiB 与 1 GiB。对于可用显存不同的设备，先保留自动分配；只有明确了解各卡负载且验证过启动行为时再手动调整。

## 验证建议

1. 保存配置，查看设备列表、主卡、单卡或多卡计划以及计划说明。
2. 重启模型，检查启动日志中的拆分方式、分配权重和卸载层数。
3. 使用预期上下文长度与真实 TTS、VRM 负载，观察各卡显存、模型响应速度和是否出现显存不足。
4. 若显存不足，提高预留、缩短上下文、选择更小模型或量化，再重新验证。若多卡更慢，比较 `auto` 与 `off`。

管理器的权重预算与上下文建议是估算，不保证加载成功、能达到某个上下文长度或获得加速。其他程序的资源变化、模型结构和实际运行开销都会影响结果。

## 本机验证与复测入口

RTX 3060 Ti 8GB + RTX 5060 Ti 16GB 已验证：Bonsai PQ2 在 32K、64K 下单卡及强制双卡均成功；Qwen3.8-27B-UD-Q4_K_M 在 32K 下自动和强制双卡均确认实际上下文与完整 GPU 卸载，模型缓冲约为 3964MiB 和 10710MiB。Qwen 测试未同时加载 TTS/VRM，不能据此承诺完整直播共存。

自动模式对较小模型保留单卡，对较大模型跨卡，不保证强制双卡更快。可使用显式隔离测试复查，脚本不读取私人配置，不控制已有服务：

```powershell
python tools/probe_multi_gpu.py --run --model Qwen3.8-27B-UD-Q4_K_M.gguf --modes auto force --ctx 32768 --output 全新证据目录
```

`--model` 必须为模型库内现有 GGUF 文件名；`--ctx` 支持 16384、32768、65536。省略模型时测试 Bonsai PQ2，省略模式时比较单卡与强制双卡。报告同时核对实际上下文、完整层卸载、各卡正数模型缓冲和有效推理结果；没有证据就不通过。详细日志只属于本次隔离子进程，原有配置和服务不会被接管。
